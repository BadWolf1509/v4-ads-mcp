# S1–S3 (achados do smoke de 14/11) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** corrigir a lista estática do `list_gaql_resources` (S1), tirar do token o `update_rsa` que não muda nada (S2) e criar a tool `remove_ad` (S3).

**Architecture:** três PRs independentes, nesta ordem, cada um a partir de `main` já com o anterior mergeado (S2 e S3 regravam o mesmo snapshot de schemas). S1 é dado + guard offline contra o proto do SDK. S2 estende o pré-flight que já lê o RSA. S3 segue o molde do N3 (`update_recommendation_subscription`): pré-flight por GAQL, token sempre, builder registrado, confirmador com releitura em `conferencia`.

**Tech Stack:** Python 3.13, `google-ads` (API v25, proto-plus), pytest.

**Spec:** [`docs/superpowers/specs/2026-11-14-s1-s3-design.md`](../specs/2026-11-14-s1-s3-design.md)

## Global Constraints

- A resposta pós-write não vira erro (F83/F91): falha de releitura → `confirmation_error`, sucesso de pé.
- Campo não lido é `None`; enum se compara por `.name` (F145). Lista vazia de headlines/`final_urls` num RSA = não lido.
- Schema sem `type` em lista nem `oneOf`/`anyOf`/`allOf`; todo array com `maxItems` (F183).
- Ids entram em GAQL por `str(int(x))` (F87).
- `efeito`/`changed_count` = ACK do Google; o veredito da releitura vai em `conferencia: {campo, pedido, relido, motivo}` (contrato do #255). Nenhum ramo novo toca `efeito`.
- Audit (`__params_summary__`) só com contagens e ids, nunca texto.
- Todo guard novo falha contra o código pré-fix — prove por sabotagem, **nunca `git checkout`**.
- Gate antes do commit: `D:/v4-ads-mcp/.venv/Scripts/python.exe scripts/check_pre_push.py > /dev/null 2>&1; echo $?` → `0`. Sem pipe entre o gate e o commit.
- Snapshot de schemas: `V4_REGRAVAR_SCHEMAS=1` só depois da mudança; o diff do `tests/unit/fixtures/schemas_das_tools.json` tem que tocar só as tools da task.
- Contagens de tool vêm do registry (`import_all_tools()`), nunca de grep.
- Commits `fix(mcp): …` / `feat(mcp): …` com o trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **S3, `ad_id` que aparece em mais de um `ad_group_ad`** (a GAQL por `ad.id` devolve N linhas): recusa citando os grupos, sem token — remover em todos sem o gestor ver seria o pior caso. Teste na Task 3.
2. **S3, lote em que todos os ENABLED do grupo estão sendo removidos juntos** (não só o último): o aviso de "último ENABLED" conta os que sobram **depois do lote**. Teste na Task 3.
3. **S2, `final_urls` com a mesma URL em outra ordem ou com barra final diferente:** conta como diferente (comparação exata de lista). É o lado seguro; teste na Task 2.
4. **S2, item que só traz `remover_pinos: true` junto de textos iguais:** é no-op (a flag não é campo mutável). Teste na Task 2.
5. **S3, releitura que não acha o anúncio:** `conferencia: None` (não lido), nunca divergência. Teste na Task 3.
