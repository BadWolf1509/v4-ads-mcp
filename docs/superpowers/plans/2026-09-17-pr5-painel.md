# PR 5 — Painel: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Partir `src/web/routes.py` (1839 linhas, 42 rotas) em dez módulos por
responsabilidade, e fechar as quatro correções de corretude que o arquivo
monolítico escondia — 36 leituras sem proteção de reconexão, isenção de CSRF por
prefixo, uma rota de mutação sem guard de admin, e mudança de acesso que grava a
linha de auditoria fora da transação.

**Architecture:** O split é **movimentação sem mudança de comportamento**, e é
provado como tal: a Task 1 escreve um guard que fixa a tabela de rotas do app
(método, caminho, nome do endpoint, dependências) **antes** de qualquer arquivo
se mexer; o split só é aceito se aquele guard passar sem uma linha de alteração.
Toda correção de lógica vai em commit separado, depois, para o diff do split
permanecer legível. Nenhum mecanismo novo: `run_with_reconnect`,
`conn.transaction()` e `_require_admin` já existem no repo e são aplicados onde
faltam.

**Tech Stack:** Python 3.13 · FastAPI + Jinja2 + HTMX 2 · asyncpg (SQL cru) ·
pytest + testcontainers · AST-based guards sobre `tests/unit/_guard_harness.py`

**Spec:** [`docs/superpowers/specs/2026-09-06-correcoes-varredura-design.md`](../specs/2026-09-06-correcoes-varredura-design.md), seção "PR 5 — Painel"

## Global Constraints

- **O split não muda comportamento.** Se durante a Task 2 você quiser corrigir
  algo que viu, **não corrija** — anote no relatório. As correções têm tarefas
  próprias, depois. Um split com fix embutido é um diff que ninguém consegue
  revisar.
- **`run_with_reconnect` NUNCA envolve escrita** (F91): o retry re-executa a
  escrita. Envolva só leitura idempotente; escrita fica fora, ou protegida por
  `best_effort`. Ler-e-depois-escrever no mesmo closure é escrita.
- **Isenção de CSRF é por ROTA, nunca por prefixo** (F106): prefixo herda tudo
  que um `APIRouter(prefix=…)` pendurar ali depois, sem revisão.
- **POST de mutação sem HTMX devolve 303, não 200** (F107) — senão o refresh
  re-executa a ação. Com `hx-post`, devolve `204` + `HX-Redirect`/`HX-Refresh`,
  nunca 303 cru (F96).
- **Nenhum JS ou CSS inline em template** (`onclick=`, `hx-on`, `<script>`,
  `style=`): a CSP não tem `unsafe-*` e o handler morre calado. Use
  `data-v4-*` + listener em `v4-panel.js`.
- **Não mexa em classe utilitária de template sem rodar
  `python scripts/build_tailwind.py` e commitar o CSS no MESMO commit** — o CI
  faz `git diff --exit-code`.
- **`CLAUDE.md` está a 13 bytes de um teto que o gate confere.** Não acrescente
  linha nenhuma a ele nesta PR.
- **Todo guard novo ou apertado precisa da mutação que o derruba, provada**:
  sabote, veja vermelho, desfaça, veja verde. Mais um **controle positivo** —
  sabotagem sozinha não prova guard. Para guard *apertado*, prove também que o
  **antigo passava verde** onde o novo acusa.
- **Gate antes de todo commit:** `python scripts/check_pre_push.py` — rode mudo
  (`> /dev/null 2>&1`) e leia `$?`. **Nunca** ponha pipe entre o gate e o `&&`.
  Nas tarefas que mexem em query, transação ou migration, o **full sweep é
  obrigatório**: `python scripts/check_pre_push_full.py` (Docker).
- **Mensagem de commit com crase, `$` ou `!` vai por heredoc `<<'MSG'`**, nunca
  por `-m "..."` — crase dentro de aspas duplas é substituição de comando.
- Commits: `refactor(web): …` / `fix(web): …` / `test(web): …`. Escopos válidos:
  `web`, `admin`, `auth`, `db`, `mcp`, `meta_ads`, `ci`, `design-system`,
  `security`. Trailer `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

- [ ] **Step 1: Escreva o guard contra o código ATUAL**

Crie `tests/unit/test_tabela_de_rotas_e_estavel.py`:

```python
"""A tabela de rotas do painel é um contrato — o split não pode mexer nela.

Este guard nasce ANTES do split (PR 5, Task 1) e existe para uma coisa só:
tornar falseável a afirmação "movimentação sem mudança de comportamento". A
suíte passar não basta — uma rota que trocasse de método, de caminho ou de
guard de autenticação no meio de um recorte de 1839 linhas passaria em todo
teste que não a exercitasse.

O snapshot é a lista ORDENADA de (método, caminho, nome do endpoint, nomes das
dependências). Inclui as dependências de propósito: perder um
`Depends(current_manager)` num recorte é exatamente o tipo de erro que o split
pode introduzir, e ele não muda nem método nem caminho.
"""

from __future__ import annotations

import json
from pathlib import Path

from fastapi.routing import APIRoute

from src.web.routes import router

_SNAPSHOT = Path(__file__).resolve().parent / "fixtures" / "tabela_de_rotas.json"


def _tabela() -> list[dict[str, object]]:
    linhas: list[dict[str, object]] = []
    for r in router.routes:
        if not isinstance(r, APIRoute):
            continue
        deps = sorted(
            d.call.__name__
            for d in r.dependant.dependencies
            if getattr(d, "call", None) is not None and hasattr(d.call, "__name__")
        )
        linhas.append(
            {
                "path": r.path,
                "methods": sorted(r.methods),
                "name": r.name,
                "deps": deps,
            }
        )
    return sorted(linhas, key=lambda x: (str(x["path"]), str(x["methods"])))


def test_a_tabela_de_rotas_bate_com_o_snapshot() -> None:
    atual = _tabela()
    assert _SNAPSHOT.exists(), (
        f"snapshot ausente em {_SNAPSHOT}. Ele é gravado UMA vez, antes do "
        "split, e nunca regenerado para fazer um teste passar — regenerar é "
        "apagar a única prova de que o split não mudou comportamento."
    )
    esperado = json.loads(_SNAPSHOT.read_text(encoding="utf-8"))
    assert atual == esperado, (
        "a tabela de rotas mudou. Se foi o split, ele NÃO foi movimentação "
        "pura — compare linha a linha e reponha o que se perdeu. Se a mudança "
        "é intencional (rota nova), atualize o snapshot no MESMO commit que a "
        "introduz, e diga por quê na mensagem."
    )


def test_o_snapshot_nao_esta_vazio() -> None:
    """Controle positivo: snapshot vazio faria o teste acima passar por vacuidade."""
    esperado = json.loads(_SNAPSHOT.read_text(encoding="utf-8"))
    assert len(esperado) >= 40, (
        f"snapshot tem {len(esperado)} rotas; o painel tinha 42 quando este "
        "guard foi escrito. Um snapshot truncado passa por vacuidade."
    )
```

```python
`current_manager` responde "quem é você"; `_require_admin` responde "você

mesma lógica vale para qualquer isenção larga.

from __future__ import annotations

from fastapi.routing import APIRoute

from src.web import create_app

# Rotas POST que legitimamente NÃO exigem admin, cada uma com o motivo.
_SEM_ADMIN_COM_MOTIVO = {
    # <preencha ao rodar pela primeira vez: cada rota que aparecer e for
    # legítima entra aqui com uma frase dizendo por que um gestor comum pode
    # disparar. Login e logout são os óbvios.>
}


def test_toda_rota_post_do_painel_exige_admin_ou_tem_motivo() -> None:

        if not isinstance(r, APIRoute) or "POST" not in r.methods:
            continue

        deps = {
            d.call.__name__
            for d in r.dependant.dependencies
            if getattr(d, "call", None) is not None and hasattr(d.call, "__name__")
        }
        if "_require_admin" in deps:
            continue
        if r.path in _SEM_ADMIN_COM_MOTIVO:
            continue
        ofensores.append(f"{r.path} ({r.name})")

    assert examinadas, (
        "o scanner não viu nenhuma rota POST — guard que varre zero passa por "

        "Ou acrescente a dependência, ou registre em `_SEM_ADMIN_COM_MOTIVO` "
        "com uma frase dizendo por que um gestor comum pode disparar."
    )
```

## Task 4: CSRF por rota, não por prefixo

**Files:**
- Modify: `src/web/middleware.py:19-23` e `:106`
- Test: `tests/unit/test_csrf_por_rota.py` (criar)

**Interfaces:**
- Consumes: nada de tarefas anteriores.
- Produces: nada.

**O bug:** `_CSRF_EXEMPT_PREFIXES = ("/oauth/meta/data-deletion-callback", "/mcp")`
e a checagem é `path.startswith(_CSRF_EXEMPT_PREFIXES)`. Um `APIRouter(prefix=…)`

**O que o keyset resolve e o desempate não:** `OFFSET n` faz o Postgres varrer e
descartar as n primeiras linhas a cada página — custo que cresce com a
profundidade. E, com linhas sendo **inseridas** durante a navegação, o offset
desliza: a página 2 repete o que entrou na 1. O keyset ancora na última linha
vista (`(occurred_at, id) < (último_occurred_at, último_id)`), então nem varre
nem desliza.

3. **Com uma inserção entre a página 1 e a 2**, o keyset não repete o que já
   foi visto — este é o caso que o `OFFSET` erra e que o desempate sozinho não
   conserta.
