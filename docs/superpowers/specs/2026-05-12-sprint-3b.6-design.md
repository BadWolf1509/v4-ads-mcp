## 1. Goal

Ship `remove_audience` — single MCP tool pra detach audience criteria (user_list OU user_interest) anexadas a ad_group ou campaign existente. Completa o CRUD do audience (Sprint 3b.4 create + Sprint 3b.5 validation + agora delete) e resolve real debt: 5 orphan criteria acumuladas em Nutry sandbox dos smoke runbooks de Sprints 3b.4-3b.5.

## 2. Scope decisions (3 perguntas resolvidas via brainstorming 2026-05-12)

| # | Decisão | Resolução | Justificativa |
|---|---|---|---|
| 1 | Tool surface shape | **Pattern A** — top-level `target_type` + `target_id` (singular) + `criterion_ids` array | Mirror `remove_negative_keywords` (precedente V4) + `apply_audience` discriminator. 1 target por call simplifica + alinha com cleanup workflow real (criteria do mesmo ad_group/campaign juntos). Gestor não precisa construir resource_names |
| 2 | Classification + cap | **Sempre CONFIRM, cap 100** | Spec §7.1 "Remove qualquer coisa = sempre confirma". Audience removal pode ter impact biz (exclusion removal restaura audience à delivery pool). Friction trivial (1 apply_change). Cap 100 alinha com apply_audience (audience ops são deliberadas) |
| 3 | Per-row error handling | **partial_failure=True + per-row mapping** | Mirror apply_audience pattern. Idempotência state-wise importante pra cleanup (re-run = no-op em criteria já removidas). Defensive `_classify_partial` mapping pra `RESOURCE_NOT_FOUND` → `"already_removed"` |

### 3.2 Custom params_summary

```python
def _build_params_summary(target_type: str, target_id: str, criterion_count: int) -> dict[str, Any]:
    """Audit-safe summary: aggregate counts only.

    target_id is OK to include (numeric campaign/ad_group ID — no competitive signal).
    criterion_ids list NOT included (they are deterministic from existing audience attachments,
    no signal beyond count).
    """
    return {
        "target_type": target_type,
        "target_id": target_id,
        "criterion_count": criterion_count,
    }
```

### 3.3 Per-row error mapping

```python
_ALREADY_REMOVED_PATTERNS = (
    "RESOURCE_NOT_FOUND",
    "NOT_FOUND",
    "DOES_NOT_EXIST",
    "CRITERION_NOT_FOUND",
)


def _classify_partial(error: str | None) -> str:
    """Map a Google Ads partial-failure error to per-row status.

    Defensive guard pattern (like Sprint 3b.3 A1 silent dedupe) — Google may
    silently succeed on remove-already-removed OR may return NOT_FOUND error.
    Mapping handles either case for graceful idempotency.
    """
    if error is None:
        return "removed"
    upper = error.upper()
    if any(p in upper for p in _ALREADY_REMOVED_PATTERNS):
        return "already_removed"
    return "failed"
```

Used internally by `run_mutation` audit_log row generation. Note: `apply_change` (existing tool used to consume the token) doesn't surface per-row status to the caller — visibility is at audit_log level only. Future enhancement: extend `apply_change` to return per-row `removed[]` array (out of scope this sprint).

### 3.4 Builder — `src/google_ads/mutates/audiences.py` (append)

```python
@register_builder("remove_audience")
def build_remove_audience(
    client: Any, customer_id: str, payload: dict[str, Any]
) -> list[Any]:
    """payload: {target_type: 'ad_group'|'campaign', target_id: str, criterion_ids: [str]}

    Each criterion_id becomes one MutateOperation with remove (not create):
      - target_type='ad_group' → ad_group_criterion_operation.remove = resource_name
        Resource format: customers/{cid}/adGroupCriteria/{target_id}~{criterion_id}
      - target_type='campaign' → campaign_criterion_operation.remove = resource_name
        Resource format: customers/{cid}/campaignCriteria/{criterion_id}
        (FLAT path — campaign_criterion has no compound key)
    """
    target_type = payload["target_type"]
    target_id = payload["target_id"]
    criterion_ids = payload["criterion_ids"]

    ops: list[Any] = []
    for crit_id in criterion_ids:
        op = client.get_type("MutateOperation")
        if target_type == "ad_group":
            crit_op = op.ad_group_criterion_operation
            crit_op.remove = (
                f"customers/{customer_id}/adGroupCriteria/{target_id}~{crit_id}"
            )
        else:  # campaign
            crit_op = op.campaign_criterion_operation
            crit_op.remove = f"customers/{customer_id}/campaignCriteria/{crit_id}"
        ops.append(op)
    return ops
```

**Critical correctness detail:** `AdGroupCriterion.resource_name` uses `~` separator (compound key with ad_group_id), while `CampaignCriterion.resource_name` is flat (just criterion_id). Builder constructs paths inline to avoid SDK helper signature inconsistencies. Validated against the resource_name format returned by `get_audience_performance` (Sprint 3b.4 read tool).

## 5. Error handling

**Schema-level (MCP transport rejection — pre-tool):**
1. `customer_id` 10-digit
2. `target_type` enum (ad_group | campaign)
3. `target_id` digits
4. `criterion_ids` minItems=1, maxItems=100, items digits
5. `additionalProperties=false` no top-level + items

**No pre-flight in-tool validation needed** (criterion_ids são digits puros sem resource_name formats pra checar). Google's mutate per-row + partial_failure handles missing criteria graciously.

**Per-row partial_failures via `run_mutation`:**

| Google error pattern | Per-row status (audit_log) |
|---|---|
| Sucesso (None error) | `"removed"` |
| `RESOURCE_NOT_FOUND`, `NOT_FOUND`, `DOES_NOT_EXIST`, `CRITERION_NOT_FOUND` | `"already_removed"` (idempotent) |
| `OPERATION_NOT_PERMITTED_FOR_CONTEXT` (PMAX, etc) | `"failed"` + error |
| target_type mismatch (gestor passa ad_group mas criterion é campaign-level) | `"failed"` + error |
| Outros | `"failed"` + error |

## 6. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Gestor passa target_type errado pra criterion (ad_group when campaign-level) | Medium | Google retorna error per-row; partial_failure mantém os outros operacionais; audit_log mostra `"failed"`. Docstring documenta restrição |
| `~` separator confusion (compound key for ad_group vs flat campaign path) | Medium | **ProtoFieldCapture tests explicitamente verificam path format** (regression test #4 + #5). Bug aqui seria runtime, mas test pega em unit |
| Re-running cleanup batch após algumas criteria já removidas | High (cleanup is iterative) | partial_failure mapping → `"already_removed"`. Defensive guard from Sprint 3b.3 A1 lesson |
| Google silent-removes already-removed instead of NOT_FOUND error | Medium | Sprint 3b.3 A1 finding pattern. Mapping handles both cases — if Google returns None error (silent success), status = `"removed"` (idempotent-safe); if Google returns NOT_FOUND, status = `"already_removed"`. Either way, no spurious failures |
| Per-row response visibility limited (apply_change doesn't surface) | Low | Documented in docstring + spec §3.3. Future enhancement: extend apply_change. Audit_log provides visibility |
| ProtoFieldCapture fixture missing edge case | Low | 6 builder tests cover ad_group + campaign + multi-criterion + edge cases (empty list, ~-separator) |
