## 3. Component specs

### 3.1 Helper compartilhado em `src/google_ads/queries/_common.py`

```python
def value_proxy_warning(conversions: float, conversions_value: float) -> str | None:
    """Returns warning string PT-BR if conversions_value == conversions (1:1 placeholder
    tracking), else None.

    Real revenue tracking would have value != count (unless every conversion is
    coincidentally R$ 1.00 — extremely unlikely). 1:1 ratio strong signals that
    conversion action uses default value=1.0 BRL placeholder, making ROAS misleading.

    Sprint 3b.7 (P1b dogfood UX-1 finding).
    """
    if conversions > 0 and conversions == conversions_value:
        return (
            "conversions_value == conversions (1:1 ratio). Tracking provavelmente "
            "sem revenue real — ROAS pode ser misleading."
        )
    return None
```

### 3.2 Enum decode fix — 10 read tools

**Pattern atual (broken):**
```python
"status": str(row.campaign.status).split(".")[-1],     # → "2"
"type": str(row.campaign.advertising_channel_type).split(".")[-1],  # → "2"
```

**Pattern fixed:**
```python
"status": row.campaign.status.name,                    # → "ENABLED"
"type": row.campaign.advertising_channel_type.name,    # → "SEARCH"
```

**Files affected (10):**

| File | Enums to decode |
|---|---|
| `src/mcp/tools/get_ad_group_performance.py` | status |
| `src/mcp/tools/get_ad_performance.py` | status, type, ad_strength |
| `src/mcp/tools/get_campaign_performance.py` | status, advertising_channel_type |
| `src/mcp/tools/get_conversion_actions.py` | status + various |
| `src/mcp/tools/get_device_performance.py` | device type |
| `src/mcp/tools/get_hourly_performance.py` | day_of_week (provavelmente) |
| `src/mcp/tools/get_keyword_performance.py` | status, match_type |
| `src/mcp/tools/get_negative_keywords_audit.py` | match_type |
| `src/mcp/tools/get_search_terms_report.py` | status (UX-3 case) |
| `src/mcp/tools/get_top_keywords_creatives.py` | status, match_type |

**Edge case:** alguns campos podem ser strings genuínas (não enums) e `.name` daria AttributeError. Implementer deve verificar cada call site — se for enum, usa `.name`; se for string (e.g., `row.ad_group_ad.ad.name`), mantém `str(...)`.

Net delta: ~25-30 source LOC changed (each replacement is 1 line).

### 3.3 UX-1 warning integration

**`src/mcp/tools/get_account_overview.py`** — integrar warning em current + previous aggregates:

```python
from src.google_ads.queries._common import value_proxy_warning

# After computing current aggregate:
current_obj = {
    "impressions": ...,
    # ... existing fields ...
    "roas": round(conv_val / micros_to_currency(cost), 2) if cost else 0.0,
}
warning = value_proxy_warning(current_obj["conversions"], current_obj["conversions_value_brl"])
if warning:
    current_obj["tracking_warning"] = warning

# Same pattern for previous_obj
```

**`src/mcp/tools/get_funnel_metrics.py`** — mesmo pattern (também tem `current` + `previous`).

**Conditional field:** `tracking_warning` aparece APENAS quando ratio 1:1 detectado. Quando ausente = real revenue tracking. Zero breaking change.

## 5. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Some `.split(".")[-1]` call sites are NOT enums (genuine strings) | Medium | Implementer verifies each replacement per file — use `.name` only for enum types. Most are obvious from context |
| `tracking_warning` field added but legacy consumers fail | Very Low | Zero external consumers (Web panel doesn't consume these tools; Wellington solo) |
| `.name` attribute behaves differently across proto-plus versions | Low | Verified empirically (`str(CampaignStatus.ENABLED)` returns `"2"` but `.name` returns `"ENABLED"` reliably). Standard proto-plus API |
| All V4 accounts use placeholder tracking → warning shows everywhere | Medium-likely | This is **desired behavior** — warning IS the value. If 100% accounts show warning, that's a finding that V4 setup pattern has tracking gap |
| Test updates miss some `.split(".")[-1]` assertions in existing tests | Medium | Implementer greps tests for `"2"` literal string assertions on status fields + updates |
