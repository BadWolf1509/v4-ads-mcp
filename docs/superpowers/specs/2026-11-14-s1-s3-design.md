## S1 — lista estática de `segments` com campo inexistente

**Medido em 14/11** (`validate_gaql` na MO):
- `segments.network_type` → "Unrecognized field";
- `segments.ad_network_type` e `segments.hour` em `campaign` → válidos.

`hour` não é bug, porque a lista é genérica. O defeito é a lista não dizer isso.

**Abordagens.**
- *Escolhida:* corrigir e travar contra o proto do SDK. Não chama a API e não apodrece.
- Remedir na API em CI: descartada, porque custa cota e depende de credencial.

**Desenho.**
- Em `src/google_ads/queries/meta.py`, `segments.network_type` vira `segments.ad_network_type`.
- **Guard novo:** todo item de `SEGMENTS`, e todo campo de `RESOURCES`, existe no proto do SDK
  instalado. O caminho pontuado é resolvido contra `GoogleAdsRow`. Teste offline, verificado por
  sabotagem.
- A descrição do `list_gaql_resources` passa a dizer: "a lista sem `resource` é genérica; a
  compatibilidade por recurso vem de `resource` + `customer_id`". O snapshot é regravado só para essa
  tool.

## S2 — `update_rsa` com valor igual ao atual entra no token

**Medido no smoke:** 27 de 27 com a mesma `final_url` saíram como mudança. Aplicados, seriam 27
writes sem efeito.

**Desenho.**
- O pré-flight `validate_existing_rsas_for_update`, que já lê headlines e descriptions, passa a ler
  também `final_urls`, `path1` e `path2` na **mesma** GAQL. Não há round-trip novo.
- Para cada update, compara cada campo pedido com o atual:
  - headlines e descriptions: lista de `(texto, pino)` na ordem;
  - `final_urls`: lista;
  - paths: string, com omitido/`None` igual a `""`.
- Um item cujos campos pedidos são **todos** iguais ao atual é um no-op:
  - sai do payload do token;
  - entra no preview em `sem_mudanca: [{ad_id, campos}]`;
  - o resumo diz "N de M sem mudança".
- Se **todos** os itens forem no-op, não há token. A resposta é `no_changes` ("nada a mudar"), como
  no "ja esta X" do N3.
- Item com algum campo diferente entra inteiro, como hoje.
- Campo atual não lido conta como diferente. O item fica no token: não se afirma no-op sem medir.
- **Guards:**
  - 27 itens iguais → sem token;
  - lote misto → token só com os diferentes, e os iguais listados;
  - campo não lido → fica no token;
  - item string × objeto sem pino → iguais;
  - pino diferente com o mesmo texto → diferente.

## S3 — `remove_ad` (tool nova)

**Por quê:** o MCP não tem como remover anúncio. O `update_ad_status` aceita só ENABLED/PAUSED e
auto-aplica até 5. Remoção é **irreversível**.

**Abordagens.**
- *Escolhida:* tool própria `remove_ad`, sempre com token.
- REMOVED no `update_ad_status`: descartada, porque mistura operação reversível com irreversível
  numa tool que auto-aplica.
- Não fazer: descartada pelo Wellington.

**Desenho.**
- **Schema:** `{customer_id, ad_ids: [^[0-9]+$], maxItems 20, uniqueItems}`. Descrição `[DEFER]`
  dizendo que a remoção é irreversível.
- **Pré-flight**, uma GAQL `FROM ad_group_ad` pelos `ad_id`: `ad_group.id`, `ad_group.name`,
  `campaign.name`, `ad_group_ad.status`, `system_managed_resource_source`, `ad.type`, e a contagem de
  anúncios ENABLED por grupo, numa segunda GAQL só dos grupos envolvidos. Recusa:
  - `ad_id` inexistente;
  - variação de experimento (`AD_VARIATIONS`, F181), apontando para o anúncio base.
- **Sem token** quando todos já estão REMOVED ("ja esta REMOVED"). Os que já estão REMOVED saem do
  lote misto.
- **Preview:** grupo, campanha, status atual e o aviso "**último anúncio ENABLED do grupo — o grupo
  para de servir**" quando aplicável. Mais o aviso fixo de irreversibilidade.
- **Risco:** CONFIRM fixo em `blast_radius`.
- **Execução:** `GoogleAdsService.mutate` com `ad_group_ad_operation.remove =
  customers/{c}/adGroupAds/{ag}~{ad}` e `partial_failure`.
- **Pós-write:** releitura numa GAQL (`ad_group_ad.status`) → `conferencia` com campo `status`
  (`REMOVED` esperado), no contrato do #255. `efeito` e `changed_count` ficam intocados. A falha da
  releitura vira `confirmation_error`.
- **Audit:** só contagens e ids, sem texto.
- **Guards:**
  - variação recusada;
  - "ja esta REMOVED" sem token;
  - aviso de último ENABLED;
  - releitura divergente vira `conferencia` sem rebaixar `efeito`;
  - CONFIRM fixo;
  - registro nas tabelas de tools e gates.
- **Prova:** com o gestor presente, em sessão nova. Criar um RSA PAUSED no CONTAINER e removê-lo pela
  tool, que é o passo 2.5 do roteiro.
