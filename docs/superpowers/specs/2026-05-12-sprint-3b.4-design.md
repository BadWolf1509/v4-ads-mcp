# Sprint 3b.4 Design — `apply_audience`

**Date:** 2026-05-12
**Author:** Claude (Sonnet 4.7) em sessão dirigida por wellinton.ribeiro@v4company.com
**Status:** APPROVED — pronto para writing-plans

## 1. Goal

Ship `apply_audience` — single MCP tool pra anexar audience criteria (positive observation OU negative exclusion) a `ad_group` ou `campaign` existente. Habilita 2 workflows do V4 skill `analise-performance-google-ads`:

1. **Observation pra audit:** anexar in-market segments (`user_interest`) como observation pra medir overlap entre ICP e quem realmente converte.
2. **Customer Match exclusion:** anexar lista de clientes (`user_list` CRM_BASED) como `negative=True` em campanhas de aquisição, esperando -10% CPA (V4 playbook explícito).

## 2. Scope decisions (5 perguntas resolvidas via brainstorming 2026-05-12)

| # | Decisão | Resolução |
|---|---|---|
| 1 | Audience types suportados | `user_list` + `user_interest` (matches read side `get_audience_performance`). YAGNI em `custom_audience`/`combined_audience`/`audience`/demographics |
| 2 | Modes | `observation` + `exclusion`. **Dropped `targeting`** — exige update atômico de `campaign.targeting_setting` (+200 LOC sem use case V4 explícito) |
| 3 | Target shape | 1 tool com top-level `target_type: ad_group \| campaign`. Mirror `bulk_pause_by_query` (Sprint 3b.2) |
| 4 | Batch shape | `mode` top-level + cap 100 attachments. Per-call mode (não per-item) simplifica classification |
| 5 | bid_modifier | Optional em observation (range 0.1-10.0). Rejected em exclusion (semanticamente N/A) |

## 3. Tool spec

### 3.1 Purpose

Cria N AdGroupCriterion ou CampaignCriterion ops via partial_failure mutate, anexando audience resources existentes (user_list ou user_interest IDs) com mode-controlled negative flag + bid_modifier opcional.

### 3.2 Input schema

```json
{
  "type": "object",
  "properties": {
    "customer_id": {"type": "string", "pattern": "^[0-9]{10}$"},
    "target_type": {"type": "string", "enum": ["ad_group", "campaign"]},
    "mode": {"type": "string", "enum": ["observation", "exclusion"]},
    "attachments": {
      "type": "array",
      "minItems": 1,
      "maxItems": 100,
      "items": {
        "type": "object",
        "properties": {
          "target_id": {"type": "string", "pattern": "^[0-9]+$"},
          "audience_type": {"type": "string", "enum": ["user_list", "user_interest"]},
          "audience_resource_name": {
            "type": "string",
            "pattern": "^customers/[0-9]{10}/(userLists|userInterests)/[0-9]+$"
          },
          "bid_modifier": {"type": "number", "minimum": 0.1, "maximum": 10.0}
        },
        "required": ["target_id", "audience_type", "audience_resource_name"],
        "additionalProperties": false
      }
    }
  },
  "required": ["customer_id", "target_type", "mode", "attachments"],
  "additionalProperties": false
}
```

### 3.3 Classification (`blast_radius.py`)

```python
if operation == "apply_audience":
    mode = (params or {}).get("mode")
    target_count = (params or {}).get("target_count", 0)
    if mode == "exclusion":
        return RiskClassification(
            CONFIRM,
            "apply_audience: exclusion mode — sempre confirma (delivery impact)"
        )
    if target_count <= 0:
        return RiskClassification(
            CONFIRM,
            f"apply_audience: target_count={target_count} desconhecido — confirmar"
        )
    if target_count <= 20:
        return RiskClassification(
            AUTO,
            f"apply_audience observation ({target_count} attachments) — auto"
        )
    return RiskClassification(
        CONFIRM,
        f"apply_audience: observation com >20 attachments ({target_count}) — confirmar"
    )
```

**Threshold rationale:**
- `mode=observation`: AUTO ≤20 alinha com `add_keywords` (Sprint 3b.3) — additive sem impacto direto em delivery
- `mode=exclusion`: **sempre CONFIRM**, mesmo count=1 — exclusion remove segment do leilão, pode ter impact biz alto (V4 estima -10% CPA pra Customer Match exclusion)

### 3.5 Validation rules

**Schema-level (MCP transport rejects before tool runs):**
1. `customer_id` 10-digit pattern
2. `target_type` enum
3. `mode` enum
4. `attachments` minItems=1 / maxItems=100
5. Each item: `target_id` digits, `audience_type` enum, `audience_resource_name` regex
6. `bid_modifier` range 0.1-10.0 quando presente

**Pre-flight in-tool (após schema, antes da mutation):**

7. **`bid_modifier` + exclusion incompatibility:**
   ```python
   if mode == "exclusion":
       offending = [i for i, a in enumerate(attachments) if "bid_modifier" in a]
       if offending:
           return {"status": "error", "error": f"bid_modifier nao eh permitido em mode=exclusion (attachments[{offending}] invalido(s))"}
   ```

8. **`audience_type` vs resource_name path consistency:**
   ```python
   for i, att in enumerate(attachments):
       expected = "userLists" if att["audience_type"] == "user_list" else "userInterests"
       if f"/{expected}/" not in att["audience_resource_name"]:
           return {"status": "error", "error": f"attachments[{i}]: audience_type='{att['audience_type']}' incompativel com resource_name (esperado segmento /{expected}/)"}
   ```

9. **`audience_resource_name` customer_id consistency:**
   ```python
   for i, att in enumerate(attachments):
       if not att["audience_resource_name"].startswith(f"customers/{customer_id}/"):
           return {"status": "error", "error": f"attachments[{i}]: resource_name pertence a outra conta (esperado prefixo customers/{customer_id}/)"}
   ```

### 3.6 Audit `params_summary` (privacy-safe aggregate)

```python
def _build_params_summary(target_type, mode, attachments):
    audience_types = Counter(a["audience_type"] for a in attachments)
    with_bid_modifier = sum(1 for a in attachments if "bid_modifier" in a)
    unique_targets = len({a["target_id"] for a in attachments})
    return {
        "target_type": target_type,
        "mode": mode,
        "audience_types_distribution": dict(audience_types),
        "with_bid_modifier_count": with_bid_modifier,
        "unique_targets_count": unique_targets,
    }
```

**Privacy gate:** NUNCA inclui `audience_resource_name` raw (resource_names podem revelar nome da Customer Match list, IDs específicos de in-market). Só aggregate count. Integration test verifica via `assert "userLists" not in json.dumps(summary_d)` style.

### 3.7 Idempotency expectation

Per Sprint 3b.3 finding A1: Google Ads API em partial_failure mode silently deduplica duplicate adds (não retorna CRITERION_EXISTS). Esperamos mesmo behavior aqui:
- Re-anexar mesma audience ao mesmo target → state-idempotent, sem criterion duplicada
- Per-row status retorna `"attached"` (não `"already_attached"`)
- `_classify_partial` mapping pra `CRITERION_EXISTS`/`DUPLICATE_CRITERION` mantido como **defensive guard** — caso Google mude behavior

## 4. Builder spec

**Arquivo:** `src/google_ads/mutates/audiences.py` (NEW)

```python
@register_builder("apply_audience")
def build_apply_audience(client: Any, customer_id: str, payload: dict[str, Any]) -> list[Any]:
    """payload: {target_type: 'ad_group'|'campaign', mode: 'observation'|'exclusion',
                 attachments: [{target_id, audience_type, audience_resource_name, bid_modifier?}, ...]}

    Each attachment becomes one MutateOperation with either:
      - ad_group_criterion_operation.create (if target_type='ad_group')
      - campaign_criterion_operation.create (if target_type='campaign')

    Sets: status=ENABLED, negative=(mode=='exclusion'),
          user_list.user_list OR user_interest.user_interest_category,
          bid_modifier (only if present AND mode='observation').
    """
    target_type = payload["target_type"]
    mode = payload["mode"]
    attachments = payload["attachments"]
    ops: list[Any] = []

    if target_type == "ad_group":
        path_service = client.get_service("AdGroupService")
        status_enum = client.enums.AdGroupCriterionStatusEnum.ENABLED
    else:
        path_service = client.get_service("CampaignService")
        status_enum = client.enums.CampaignCriterionStatusEnum.ENABLED

    is_exclusion = mode == "exclusion"

    for att in attachments:
        op = client.get_type("MutateOperation")
        if target_type == "ad_group":
            crit_op = op.ad_group_criterion_operation
            crit = crit_op.create
            crit.ad_group = path_service.ad_group_path(customer_id, att["target_id"])
        else:
            crit_op = op.campaign_criterion_operation
            crit = crit_op.create
            crit.campaign = path_service.campaign_path(customer_id, att["target_id"])

        crit.status = status_enum
        crit.negative = is_exclusion

        if att["audience_type"] == "user_list":
            crit.user_list.user_list = att["audience_resource_name"]
        else:  # user_interest
            crit.user_interest.user_interest_category = att["audience_resource_name"]

        if "bid_modifier" in att and not is_exclusion:
            crit.bid_modifier = float(att["bid_modifier"])

        ops.append(op)

    return ops
```

## 5. Error handling

### 5.1 Per-row partial_failure mapping (`_classify_partial`)

```python
_ALREADY_EXISTS_PATTERNS = ("CRITERION_EXISTS", "DUPLICATE_CRITERION")

def _classify_partial(error: str | None) -> str:
    if error is None:
        return "attached"
    upper = error.upper()
    if any(p in upper for p in _ALREADY_EXISTS_PATTERNS):
        return "already_attached"
    return "failed"
```

### 5.2 Google errors expected

| Google error code | Per-row status | Significado |
|---|---|---|
| (none — success) | `"attached"` | Criterion criado |
| `CRITERION_EXISTS`, `DUPLICATE_CRITERION` | `"already_attached"` | Defensive guard (silent dedupe expected) |
| `USER_LIST_NOT_ACCESSIBLE` | `"failed"` + error | UserList não existe ou sem permissão MCC |
| `USER_INTEREST_NOT_FOUND` | `"failed"` + error | userInterests/ID inexistente |
| `OPERATION_NOT_PERMITTED_FOR_CONTEXT` | `"failed"` + error | Campanha PMAX ou tipo não aceita user_interest tradicional |
| `BID_MODIFIER_TOO_LOW`/`TOO_HIGH` | `"failed"` + error | (Não deveria ocorrer — schema já valida 0.1-10.0) |
| Outros | `"failed"` + error | Surface raw error PT-BR friendly se traduzido por `to_friendly`, senão message bruta |

### 5.3 Error response shape

```json
{
  "status": "error",
  "operation": "apply_audience",
  "customer_id": "...",
  "error": "PT-BR descriptive message",
  "details"?: {"attachment_index": int}    // when applicable
}
```

## 7. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Re-attaching same audience to same target | High | **Sprint 3b.3 lesson:** Google likely silent-dedupes (similar a `add_keywords`). Defensive `_classify_partial` mapping mantido. No code change needed beyond docs claiming "state-idempotent". |
| user_list não acessível pelo MCC | Medium | `USER_LIST_NOT_ACCESSIBLE` surface per-row + friendly PT-BR. Gestor pode verificar acesso via `get_audience_performance` ou Google Ads UI. |
| Campaign type rejeita audience attach (ex: PMAX limitado) | Medium | `OPERATION_NOT_PERMITTED_FOR_CONTEXT` surface per-row. Documentar em tool description: "Use em campanhas Search/Display/Video — PMAX tem audience limited a signals." |
| audience_resource_name de outra conta (typo do gestor) | Low | Pre-flight check (regra §3.5 #9) — reject ANTES de quota consumida. |
| bid_modifier 0.1-10.0 range Google API muda | Very low | Schema-level enforced; se Google ampliar range, atualizar schema com bump de minor version |
| `targeting` mode demanda futura | Medium | Out-of-scope agora. Spawn-task documentado se demanda concreta surgir. |
| Customer Match exclusion altera delivery sem aviso | Medium | **Sempre CONFIRM** em exclusion mode (mesmo count=1). PT-BR reason explica delivery impact. Apply é deliberado. |

## 8. Open questions — resolved

| # | Question | Resolution |
|---|---|---|
| 1 | Audience types supported | `user_list` + `user_interest` only — matches read side (`get_audience_performance`). Demographics + custom_audience + combined_audience + audience(new) YAGNI |
| 2 | Modes | `observation` + `exclusion`. `targeting` dropped (atomicity cost vs zero V4 demand) |
| 3 | Target type shape | Single tool, top-level `target_type` discriminator (pattern de `bulk_pause_by_query`) |
| 4 | Mode placement + cap | Mode top-level, cap 100. Per-item mode (mixing) violates YAGNI |
| 5 | bid_modifier policy | Optional in observation, rejected in exclusion. Range 0.1-10.0 schema-enforced |
| 6 | Default status of new criterion | ENABLED (active by default; gestor pode pausar via UI ou future `update_audience_status` tool) |
| 7 | Cleanup smoke approach | Leave-in-place (Nutry sandbox = zero impact). Spawn-task: `remove_audience` tool (também resolve gap Sprint 3b.3 A2) |

## 9. Out of scope (explicit)

- **`targeting` mode** (requires `campaign.targeting_setting` atomic update — +200 LOC, deferred)
- **Audience types além de user_list + user_interest** — `custom_audience`, `combined_audience`, `audience` (resource novo), demographics. Future sprint quando demanda concreta surgir.
- **Bulk detach/remove** — same Sprint 3b.3 A2 gap. Separate spawn-task.
- **Auto-creation de Customer Match list** — pre-existing user_list resources only. List creation = separate sprint (também precisa upload de CRM data).
- **bid_modifier de criterion existing** — só set no create. Update de modifier seria separate tool (matching pattern de `update_keyword_bid`).
- **Multi-target_type mixing** — uma call = um target_type. Mixar ad_group + campaign na mesma call não suportado (não há use case, e simplifica classification).
