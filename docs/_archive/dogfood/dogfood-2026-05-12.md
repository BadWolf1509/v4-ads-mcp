## UX issues encontrados

### UX-1: `conversions_value_brl == conversions` (1:1) mascara tracking placeholder

`get_account_overview` retornou:
```json
"current": {
  "conversions": 93.0,
  "conversions_value_brl": 93.0,
  "roas": 0.05
}
```

Quando `value == count` exato, é **forte sinal** de que a conta usa "value per conversion = 1.00 BRL" (default) — tracking de count de leads sem receita monetária real. Mas o overview ainda calcula e exibe `roas: 0.05` (= R$93/R$1935.68), o que é **tecnicamente correto mas semanticamente perigoso**: um gestor sem contexto da conta poderia interpretar como ROI ruim quando na verdade ROAS não está sendo medido.

**Sugestão:** `get_account_overview` deveria flag uma anomalia tipo `"value_proxy_warning": "conversions_value == conversions (provável tracking sem receita real). ROAS exibido pode ser misleading."` Mesma checagem em `get_funnel_metrics` e `get_campaign_performance`.

### UX-2: Enums proto retornados como int em vez de string legível

`get_campaign_performance`:
```json
{"campaign_id": "...", "status": "2", "type": "2", ...}
```

`status: "2"` = ENABLED, `type: "2"` = SEARCH (proto enum order). Gestor humano lendo precisa decodificar mentalmente. Outras tools (ex: `get_account_overview`) retornam números formatados — inconsistência de surface.

**Sugestão:** Normalizar enum surface em TODAS as read tools — retornar string legível ("ENABLED" / "SEARCH") ou (melhor ainda) ambas como `status: "ENABLED"` + `status_code: 2` pra retrocompat.

### UX-3: `get_search_terms_report` status com enum int sem decode

Description do schema diz: `"Status indica se ja foi adicionado como palavra-chave (ADDED) ou negativa (EXCLUDED) ou nem um nem outro (NONE)"`.

Mas resposta vem como `status: "2"` (= NONE) ou `status: "5"` (= ADDED). Inconsistência entre description (fala em ADDED/EXCLUDED/NONE) e dado retornado (números). Forces o gestor a memorizar o mapping.

**Sugestão:** Adicionar decode no nosso layer — `"status": "NONE"` ou `"NONE_NEW"` (mais legível). Manter `status_code: 2` se quiser.
