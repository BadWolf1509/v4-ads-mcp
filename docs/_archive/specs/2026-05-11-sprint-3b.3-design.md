## 1. Goal

Ship `add_keywords` — create new keywords (positive criteria) in existing ad_groups. Match_type defined at creation time. Combined with `update_keyword_status` (pause old) + `add_negatives_from_search_terms` (block bad terms), this completes the V4 skill `analise-performance-google-ads` workflow ("pause underperformer + add replacement with right match").

**Why this instead of `update_keyword_match_type`:** Empirical SDK check confirmed `KeywordInfo.text` and `KeywordInfo.match_type` are immutable post-creation (`CANNOT_MODIFY_KEYWORD_AFTER_CREATION` error). The only path to "change match_type" is remove+create — which resets Quality Score history. The V4 skills don't actually recommend match_type modification; they recommend the pause+add workflow. `add_keywords` directly supports that workflow with no API trade-offs.

**Definition of done:**

1. `add_keywords` MCP tool registered with strict JSON Schema (1 ad_group_id at top, 1-500 keywords, match_type required per keyword, cpc_bid_micros optional).
2. Classification AUTO if ≤20 keywords (per spec §7.1), CONFIRM if >20.
3. `partial_failure=True` mode used. **Sprint 3b.3 smoke 2026-05-12 finding A1:** Google does silent server-side dedupe (no `CRITERION_EXISTS` error in partial_failure response), so duplicates return per-row `"added"` (not `"already_exists"`). System remains state-idempotent — Google does not create a second criterion. The `_classify_partial` mapping is a defensive guard.
4. Custom `params_summary` in audit_log: `{ad_group_id, match_types_distribution, with_custom_bid_count}` — no raw keyword texts (privacy + competitive signal protection).
5. 10 unit tests in `test_add_keywords.py` + 2 cases in `test_blast_radius.py` + 1 integration test added; all 175+ existing tests still pass.
6. ruff + format + mypy + pytest all green locally and in CI.
7. Smoke runbook at `docs/operacao/phase-3b-3-bootstrap.md` executed by `wellinton.ribeiro@v4company.com`.

**Non-goals (YAGNI):**

- Not supporting multi-ad_group in single call (1 ad_group per call; chain if needed).
- Not modifying existing keywords (use `update_keyword_status` / `update_keyword_bid` for those).
- Not creating negative keywords (use `add_negative_keywords` / `add_negatives_from_search_terms`).
- Not setting ad_group default bid (use `update_ad_group_bid`).
- Not auto-pausing the "old" keywords being replaced — gestor decides which to pause separately.
- Not implementing `update_keyword_match_type` — API immutability + Q Score loss + skill V4 doesn't recommend modify workflow.

## 3. Tool: `add_keywords`

### 3.1 Purpose

Create N new positive keywords in 1 ad_group, each with specified text + match_type + optional cpc_bid. Mirrors `add_negative_keywords` shape (1 entity_id at top + array of items) but for `ad_group_criterion` CREATE (not `campaign_criterion` negative). Uses `partial_failure=True`. Idempotent state-wise — Google deduplicates duplicate (text, match_type) silently server-side, so re-running the same call does NOT create a second criterion (smoke finding A1).

### 3.2 Input schema

```json
{
  "type": "object",
  "properties": {
    "customer_id": { "type": "string", "pattern": "^[0-9]{10}$" },
    "ad_group_id": { "type": "string", "pattern": "^[0-9]+$" },
    "keywords": {
      "type": "array",
      "minItems": 1,
      "maxItems": 500,
      "items": {
        "type": "object",
        "properties": {
          "text": { "type": "string", "minLength": 1, "maxLength": 80 },
          "match_type": { "type": "string", "enum": ["EXACT", "PHRASE", "BROAD"] },
          "cpc_bid_micros": { "type": "integer", "minimum": 1 }
        },
        "required": ["text", "match_type"],
        "additionalProperties": false
      }
    }
  },
  "required": ["customer_id", "ad_group_id", "keywords"],
  "additionalProperties": false
}
```

Note: `match_type` is **required** per keyword (no default). Forces conscious choice — different from `add_negatives_from_search_terms` which defaults to EXACT.

### 3.3 Classification (per spec §7.1)

`blast_radius.classify(operation="add_keywords", params={target_count})`:

- **AUTO** if `target_count <= 20`
- **CONFIRM** if `target_count > 20`

Threshold of 20 is more permissive than other status ops (≤5) because:
1. ADD is additive — doesn't disrupt existing setup
2. ADD is reversible via `update_keyword_status` REMOVED/PAUSED
3. Real workflow: gestor typically adds 5-20 long-tail variations in one batch
4. Spec §7.1 explicitly sets this threshold for `Add KWs: ≤ 20 KWs em 1 ad group`

### 3.4 AUTO output

```json
{
  "status": "applied",
  "operation": "add_keywords",
  "customer_id": "1234567890",
  "ad_group_id": "183008426336",
  "applied_count": 5,
  "google_request_id": "...",
  "auto_applied_reason": "add_keywords (5 KWs em 1 ad_group) — auto",
  "added": [
    { "text": "nutricionista esportiva jp", "match_type": "PHRASE", "status": "added", "criterion_id": "..." },
    { "text": "nutri rayane jp", "match_type": "EXACT", "status": "added", "criterion_id": "..." },
    { "text": "nutricionista emagrecer", "match_type": "PHRASE", "status": "already_exists" },
    { "text": "nutri esportes", "match_type": "PHRASE", "status": "failed", "error": "<friendly PT-BR>" }
  ]
}
```

Per-row status maps:
- Google ad_group_criterion_result with criterion_id → `"added"` (+ include criterion_id in row)
- Google partial_failure_error with `CRITERION_EXISTS` or `DUPLICATE_KEYWORD` for that op → `"already_exists"`
- Any other Google error per-op → `"failed"` (+ include friendly error message)

### 3.5 CONFIRM output

```json
{
  "status": "dry_run",
  "operation": "add_keywords",
  "customer_id": "1234567890",
  "ad_group_id": "183008426336",
  "confirmation_token": "ABC12345",
  "expires_in_minutes": 10,
  "blast_summary": "Adicionar 35 KW(s) ao ad_group 183008426336. Match types: EXACT(20), PHRASE(15).",
  "to_apply": "Chame apply_change(confirmation_token=<token>) para aplicar.",
  "confirmation_reason": "add_keywords: more than 20 entities (35) — confirmar"
}
```

### 3.6 Audit log row

`run_mutation` with custom `params_summary`:

```json
{
  "ad_group_id": "183008426336",
  "match_types_distribution": { "EXACT": 3, "PHRASE": 2 },
  "with_custom_bid_count": 4
}
```

**Decisão:** raw keyword texts NOT logged — same rationale as `add_negatives_from_search_terms` (competitive signal protection). Only aggregate metadata.

### 3.7 Mutate path

`run_mutation(operation_type="add_keywords", payload={ad_group_id, keywords, __target_count__}, partial_failure=True, params_summary=...)`.

New builder `build_add_keywords` in `src/google_ads/mutates/keywords.py`:

```python
@register_builder("add_keywords")
def build_add_keywords(client, customer_id, payload):
    ad_group_id = payload["ad_group_id"]
    keywords = payload["keywords"]
    ad_group_service = client.get_service("AdGroupService")
    ad_group_resource = ad_group_service.ad_group_path(customer_id, ad_group_id)
    match_type_enum = client.enums.KeywordMatchTypeEnum
    operations = []
    for kw in keywords:
        op = client.get_type("MutateOperation")
        crit_op = op.ad_group_criterion_operation
        crit = crit_op.create
        crit.ad_group = ad_group_resource
        crit.status = client.enums.AdGroupCriterionStatusEnum.ENABLED
        crit.keyword.text = kw["text"]
        crit.keyword.match_type = match_type_enum[kw["match_type"].upper()]
        if "cpc_bid_micros" in kw:
            crit.cpc_bid_micros = int(kw["cpc_bid_micros"])
        operations.append(op)
    return operations
```

New criteria are created with `status=ENABLED` by default. Gestor can pause via `update_keyword_status` if testing/staging.

## 7. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| User adds duplicate KW (text + match_type already exists in ad_group) | High | **Sprint 3b.3 smoke 2026-05-12 finding A1:** Google API does **silent server-side dedupe** in partial_failure mode (no `CRITERION_EXISTS` error returned). System remains state-idempotent (no duplicate criterion created), but the per-row `status` is `"added"`, not `"already_exists"`. The `_classify_partial` mapping is kept as a defensive guard if Google's behavior changes. |
| cpc_bid_micros below BRL minimum | Medium | Google rejects per-op with CPC_TOO_LOW; mapped to `"failed"` with friendly PT-BR via `to_friendly()` |
| ad_group_id doesn't exist or REMOVED | Low | Google returns error per-op; surface as `"failed"` |
| Bug like 3b.2 GAQL parens (API surface assumption wrong) | Low-medium | This is mutate path (no GAQL filter). 3b.1 partial_failure handling already shipped + smoke-tested. Same pattern. |
| Brand-protection: gestor adds keyword that's a registered trademark | Medium | Google has Trademark policy enforcement that runs ASYNC after creation. We can't pre-check; document in tool description that policy review may flag later. |
| Multi-ad_group workflow (gestor wants 10 KWs across 3 ad_groups) | Low | Doc-only mitigation: tool description says "1 ad_group per call". Gestor calls 3 times. |

## 8. Open questions — resolved

| Question | Resolution |
|---|---|
| 1 ad_group_id at top vs per-keyword | **Top-level** (mirrors `add_negative_keywords`). Simpler API. |
| `match_type` required vs default to EXACT | **Required**. Forces conscious choice — different from `add_negatives_from_search_terms` (search terms imply EXACT) |
| cpc_bid_micros at item level | **Optional per item**. Omit = inherit from ad_group |
| New keyword default status | **ENABLED**. Gestor can pause via `update_keyword_status` if staging needed |
| Cap | **500 per call** (schema), **AUTO threshold 20** (per spec §7.1). Same as add_negative_keywords cap; matches spec governance rule |
| Audit raw texts | **NO** — only aggregate metadata (match_types_distribution + with_custom_bid_count). Competitive signal protection |
| Duplicate detection | **Via Google server-side dedupe** (Sprint 3b.3 smoke A1). Google silently dedupes duplicate KW adds in partial_failure mode; no `CRITERION_EXISTS` error returned. System is idempotent state-wise (no extra criterion) but per-row status reports `"added"` instead of `"already_exists"`. `_classify_partial` mapping for `CRITERION_EXISTS`/`DUPLICATE_KEYWORD` is kept as defensive guard. |
