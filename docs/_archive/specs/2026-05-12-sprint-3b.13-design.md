## 1. Goal

Ship utility MCP tool `get_my_audit_log` que retorna paginated history das operações do gestor logado via MCP (mutations + audited reads). 4 optional filter params (days, limit, customer_id, action_type) com defaults sane.

Read-only. Adds 1 new repo function (`audit_log.list_for_manager()`) + thin MCP tool wrapper.

**1 new MCP tool: count 40 → 41.**

## 2. Scope decisions

| # | Decisão | Resolução | Justificativa |
|---|---|---|---|
| 1 | Default time window | **7 days** | Match `export_csv_rows()` precedent. Weekly cadence de gestor reviews. 24h vazio em final de semana frustra UX. |
| 2 | Filter params | **Pragmatic (B)** — days + limit + customer_id + action_type | customer_id high-value (multi-account); action_type cobre "só mutations". Excluded: operation (gestor não memoriza tool names), status (debug case raro). |
| 3 | New repo function vs inline query | **New `list_for_manager()`** em `src/db/repositories/audit_log.py` | DRY (mirrors existing repo pattern), testable separately. Mirrors structure of `export_csv_rows()` mas retorna list em vez de stream CSV. |
| 4 | Response shape — include `params_summary`? | **No, omit by default** | jsonb pode ser grande. Out-of-scope to detalhar payload via tool. `audit_log.get_by_id()` existe se gestor precisar. |
| 5 | Audit this call | **Yes** | Consistent com `list_my_accounts` + `get_my_rate_limit_status`. Account-wide read. |
| 6 | `action_type` semantics | **"all" = no filter (default)**, "mutate"/"read"/"auth"/"system" = exact match | Match enum values usados pelo `record()` writer. |
| 7 | Limit defaults/max | **Default 100, max 1000** | 7-day window pra gestor real provavelmente <100 events. Cap em 1000 evita response massive. |
| 8 | Pagination beyond limit | **None (limit-only)** | YAGNI cursor-based. Se 1000+ eventos, gestor filters via `days` ou `customer_id`. |

## 3. Component specs

### 3.1 New repo function `src/db/repositories/audit_log.py::list_for_manager`

Add at end of file (after existing functions):

```python
async def list_for_manager(
    conn: asyncpg.Connection,
    *,
    manager_id: UUID,
    days: int = 7,
    limit: int = 100,
    customer_id: str | None = None,
    action_type: str | None = None,
) -> list[dict[str, Any]]:
    """Paginated list of audit_log rows scoped to a manager.

    Filters (all optional except manager_id):
    - days: time window (default 7)
    - limit: row cap (default 100, max enforced by caller schema)
    - customer_id: filter by account
    - action_type: filter by 'mutate'/'read'/'auth'/'system'; None or 'all' → no filter

    Returns rows ORDER BY occurred_at DESC, with subset of columns (omits
    params_summary to keep response compact; use get_by_id() for full detail).
    """
    where = ["manager_id = $1", "occurred_at > now() - ($2 || ' days')::interval"]
    params: list[Any] = [manager_id, str(days)]
    idx = 3
    if customer_id:
        where.append(f"customer_id = ${idx}")
        params.append(customer_id)
        idx += 1
    if action_type and action_type != "all":
        where.append(f"action_type = ${idx}")
        params.append(action_type)
        idx += 1
    params.append(limit)
    sql = f"""SELECT id, occurred_at, operation, customer_id, action_type,
                     target_count, status, duration_ms, google_request_id,
                     error_message
              FROM audit_log
              WHERE {" AND ".join(where)}
              ORDER BY occurred_at DESC
              LIMIT ${idx}"""
    rows = await conn.fetch(sql, *params)
    return [
        {
            "id": int(r["id"]),
            "occurred_at": r["occurred_at"].isoformat() if r["occurred_at"] else None,
            "operation": r["operation"],
            "customer_id": r["customer_id"],
            "action_type": r["action_type"],
            "target_count": int(r["target_count"]) if r["target_count"] is not None else None,
            "status": r["status"],
            "duration_ms": int(r["duration_ms"]) if r["duration_ms"] is not None else None,
            "google_request_id": r["google_request_id"],
            "error_message": r["error_message"],
        }
        for r in rows
    ]
```

### 3.2 Tool file `src/mcp/tools/get_my_audit_log.py`

```python
"""Tool: get_my_audit_log — paginated history das operações do gestor logado."""

import time
from typing import Any

import structlog

from src.db import connection
from src.db.repositories import audit_log
from src.mcp.context import get_current
from src.mcp.tools._registry import register_tool

log = structlog.get_logger(__name__)

_INPUT_SCHEMA: dict[str, Any] = {
    "type": "object",
    "properties": {
        "days": {
            "type": "integer",
            "minimum": 1,
            "maximum": 30,
            "default": 7,
            "description": "Janela de tempo em dias (1-30, default 7).",
        },
        "limit": {
            "type": "integer",
            "minimum": 1,
            "maximum": 1000,
            "default": 100,
            "description": "Numero maximo de eventos retornados (1-1000, default 100).",
        },
        "customer_id": {
            "type": "string",
            "pattern": "^[0-9]{10}$",
            "description": "Filtrar por uma conta especifica (opcional).",
        },
        "action_type": {
            "type": "string",
            "enum": ["mutate", "read", "auth", "system", "all"],
            "default": "all",
            "description": "Filtrar por tipo de acao. 'all' = sem filtro.",
        },
    },
    "additionalProperties": False,
}


@register_tool(
    name="get_my_audit_log",
    description=(
        "Historico das proprias operacoes do gestor via MCP (mutations + audited "
        "reads), com filtros por janela de tempo, conta, e tipo de acao. Retorna "
        "ordenado por occurred_at DESC. Scoped automaticamente ao gestor logado."
    ),
    input_schema=_INPUT_SCHEMA,
)
async def get_my_audit_log(args: dict[str, Any]) -> dict[str, Any]:
    ctx = get_current()
    started = time.monotonic()

    days = args.get("days", 7)
    limit = args.get("limit", 100)
    customer_id = args.get("customer_id")
    action_type = args.get("action_type", "all")

    pool = connection.get_pool()
    async with pool.acquire() as conn:
        events = await audit_log.list_for_manager(
            conn,
            manager_id=ctx.manager_id,
            days=days,
            limit=limit,
            customer_id=customer_id,
            action_type=action_type,
        )

    duration_ms = int((time.monotonic() - started) * 1000)

    # Audit consistent com list_my_accounts (account-wide read).
    async with pool.acquire() as conn:
        await audit_log.record(
            conn,
            manager_id=ctx.manager_id,
            session_id=ctx.session_id,
            customer_id=customer_id,
            action_type="read",
            operation="get_my_audit_log",
            target_count=len(events),
            params_summary={
                "days": days,
                "limit": limit,
                "action_type": action_type,
            },
            status="success",
            duration_ms=duration_ms,
        )

    log.info(
        "tool_get_my_audit_log",
        manager_id=str(ctx.manager_id),
        count=len(events),
        days=days,
        duration_ms=duration_ms,
    )

    return {
        "manager_id": str(ctx.manager_id),
        "filters": {
            "days": days,
            "customer_id": customer_id,
            "action_type": action_type,
        },
        "count": len(events),
        "events": events,
    }
```

## 5. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| `list_for_manager` repo query bug (params indexing) | Medium-low | Pattern mirrors existing `export_csv_rows()`. Inline review during implementation. |
| Tool returns sensitive data (other gestores' events) | Very Low | Scoped via `manager_id = $1` filter, always required. |
| 1000-row limit creates huge payload | Low-medium | Default 100 (sane); user must explicitly cap at 1000. Each row ~200 bytes → 200KB max. Acceptable. |
| `params_summary` exclusion confuses gestor | Low | Tool description doesn't mention it. If demand surfaces, add via separate `get_audit_event_detail` tool. |
| Mock pattern for repo function in tests | Low | Same pattern as Sprint 3b.12 (`get_my_rate_limit_status`). |

## 6. Out of scope

- **`get_audit_event_detail`** tool (single event with full `params_summary`) — separate Sprint if demand surfaces. Existing `audit_log.get_by_id()` repo function ready when needed.
- **Cursor pagination** — YAGNI. Filter via `days` / `customer_id` if 1000+ events.
- **Aggregation/summary** — gestor pode usar `summary_stats()` repo func (exposed via separate tool if needed). Out of scope here.
- **CSV/JSON export** — web panel `/admin/audit` already exports via `export_csv_rows()`. MCP tool é list endpoint, não export.
- **`operation` filter** — YAGNI (gestor não memoriza tool names).
- **`status` filter** — YAGNI (debug case raro).
