## 3. Tool: `add_negatives_from_search_terms`

### 3.1 Purpose

Operationalize the daily workflow `get_search_terms_report → identify bad terms → add as negatives`. Today this requires the agent to call two tools, format payloads, handle scope mapping. This tool encapsulates step 2-3.

### 3.2 Input schema

```json
{
  "type": "object",
  "properties": {
    "customer_id": { "type": "string", "pattern": "^[0-9]{10}$" },
    "negatives": {
      "type": "array",
      "minItems": 1,
      "maxItems": 500,
      "items": {
        "type": "object",
        "properties": {
          "search_term": { "type": "string", "minLength": 1, "maxLength": 80 },
          "match_type": { "type": "string", "enum": ["EXACT", "PHRASE", "BROAD"], "default": "EXACT" },
          "scope": { "type": "string", "enum": ["campaign", "ad_group", "shared_set"] },
          "scope_id": { "type": "string", "pattern": "^[0-9]+$" }
        },
        "required": ["search_term", "scope", "scope_id"],
        "additionalProperties": false
      }
    }
  },
  "required": ["customer_id", "negatives"],
  "additionalProperties": false
}
```

### 3.3 Behavior

1. Validate input via JSON Schema; reject early with PT-BR error if invalid.
2. Group negatives by `scope` (the 3 enum values map to 3 different Google Ads services).
3. For each scope group, build operations using the appropriate criterion type:
   - `campaign` → `CampaignCriterion` with `negative=True` → `CampaignCriterionService.mutate`
   - `ad_group` → `AdGroupCriterion` with `negative=True` → `AdGroupCriterionService.mutate`
   - `shared_set` → `SharedCriterion` → `SharedCriterionService.mutate`
4. Issue **at most 3 mutate calls** (one per scope group present in input), each with `partial_failure=True`. The SDK batches all operations within a scope into a single call.
5. For each input item, classify the outcome from the partial_failure response:
   - `added` — new criterion created
   - `already_exists` — Google Ads returned `CRITERION_EXISTS` or `DUPLICATE_KEYWORD` for this row; no failure
   - `failed` — other error for this row; include translated PT-BR message
6. Audit log: 1 row per call (not per item), with `params_summary` containing aggregate metadata only (see §3.5).

### 3.4 Output schema

```json
{
  "status": "applied",
  "operation": "add_negatives_from_search_terms",
  "customer_id": "1234567890",
  "applied_count": 12,
  "google_request_id": "...",
  "auto_applied_reason": "Add negativas: sempre auto (spec §7.1)",
  "added": [
    {
      "search_term": "preço grátis",
      "match_type": "EXACT",
      "scope": "campaign",
      "scope_id": "987654321",
      "status": "added"
    },
    {
      "search_term": "como fazer",
      "match_type": "EXACT",
      "scope": "campaign",
      "scope_id": "987654321",
      "status": "already_exists"
    }
  ]
}
```

### 3.5 Audit log row

```json
{
  "action_type": "mutate",
  "operation": "add_negatives_from_search_terms",
  "target_count": 12,
  "params_summary": {
    "scopes_distribution": {"campaign": 8, "ad_group": 4},
    "match_types_distribution": {"EXACT": 12},
    "scope_ids_count": 3
  },
  "status": "success"
}
```

**Decision:** Search terms themselves are NOT logged to `audit_log.params_summary`. Some V4 clients are in competitive niches; logging "concorrente X é negativa" could leak sensitive optimization signal. Only aggregate metadata.

### 3.6 Errors

All errors translated to PT-BR via existing `google_ads/errors.py`. Specific cases:

| Condition | Behavior |
|---|---|
| `negatives` array exceeds 500 | Reject at schema validation (pre-mutate) |
| Network / auth / quota / 5xx error | Raise before mutate; no items reach Google Ads |
| `scope_id` doesn't exist for the entire scope group | All items in that group marked `failed` with PT-BR error; **other scope groups proceed independently** |
| `CRITERION_EXISTS` / `DUPLICATE_KEYWORD` for individual item | Marked `already_exists`, call continues, other items in same group proceed |
| `RESOURCE_LIMIT` reached for an ad_group/campaign | Items targeting that scope_id marked `failed` with PT-BR error indicating limit; other scope_ids in same group proceed |
| Any other per-row error | Marked `failed` with translated PT-BR message; other rows continue |

### 3.7 Governance

Classification: **AUTO**. Spec §7.1: "Add negativas: Sempre auto" — negatives reduce exposure rather than expand it, low blast radius regardless of count. Same rationale as the existing `add_negative_keywords`.

Added in `src/governance/blast_radius.py`:

```python
if operation == "add_negatives_from_search_terms":
    return RiskClassification(
        level="auto",
        reason="Add negativas: sempre auto (spec §7.1)",
    )
```

## 4. Tool: `get_change_history`

### 4.1 Purpose

Unblock both `auditoria-google-ads` and `analise-performance-google-ads` skills, which today call `run_gaql` against the `change_event` resource as "CRÍTICO antes de tudo". This tool wraps that resource with structured filters, name resolution (so the agent sees "Campanha X" not `customers/123/campaigns/456`), and a summary aggregation block.

### 4.2 Input schema

```json
{
  "type": "object",
  "properties": {
    "customer_id": { "type": "string", "pattern": "^[0-9]{10}$" },
    "date_range": {
      "description": "LAST_7_DAYS (default) | LAST_30_DAYS | YESTERDAY | TODAY | ISO range {from,to}",
      "default": "LAST_7_DAYS"
    },
    "resource_types": {
      "type": "array",
      "items": {
        "type": "string",
        "enum": [
          "CAMPAIGN", "AD_GROUP", "AD_GROUP_CRITERION", "AD_GROUP_AD",
          "CAMPAIGN_CRITERION", "CAMPAIGN_BUDGET", "BIDDING_STRATEGY",
          "CONVERSION_ACTION", "CUSTOMER_NEGATIVE_CRITERION",
          "ASSET", "CAMPAIGN_ASSET", "AD_GROUP_ASSET"
        ]
      }
    },
    "operation_types": {
      "type": "array",
      "items": { "type": "string", "enum": ["CREATE", "UPDATE", "REMOVE"] }
    },
    "user_emails": {
      "type": "array",
      "items": { "type": "string", "format": "email" }
    },
    "client_types": {
      "type": "array",
      "items": {
        "type": "string",
        "enum": [
          "GOOGLE_ADS_UI",
          "GOOGLE_ADS_API",
          "GOOGLE_ADS_RECOMMENDATIONS_AUTO_APPLY",
          "GOOGLE_ADS_AUTOMATED_RULES",
          "GOOGLE_ADS_BULK_UPLOAD",
          "GOOGLE_ADS_EDITOR",
          "GOOGLE_ADS_MOBILE_APP",
          "GOOGLE_ADS_SCRIPTS",
          "GOOGLE_ADS_WEB_SERVICES",
          "OTHER"
        ]
      }
    },
    "limit": { "type": "integer", "minimum": 1, "maximum": 10000, "default": 200 }
  },
  "required": ["customer_id"],
  "additionalProperties": false
}
```

### 4.3 Validation

- `date_range` resolved against America/Sao_Paulo (consistent with existing read tools).
- **Hard limit: range cannot exceed 30 days** — Google Ads `change_event` API limit. Validated before GAQL is built; PT-BR error if exceeded ("Janela máxima de 30 dias para histórico de mudanças — limite da API do Google Ads").
- All array filters default to "no restriction" when omitted.

### 4.4 GAQL query

Generated query template:

```sql
SELECT
  change_event.change_date_time,
  change_event.user_email,
  change_event.client_type,
  change_event.change_resource_type,
  change_event.change_resource_name,
  change_event.resource_change_operation,
  change_event.changed_fields,
  change_event.campaign,
  change_event.ad_group
FROM change_event
WHERE change_event.change_date_time BETWEEN '<from>' AND '<to>'
  -- conditional clauses appended only when filter is provided:
  [AND change_event.change_resource_type IN (...)]
  [AND change_event.resource_change_operation IN (...)]
  [AND change_event.user_email IN (...)]
  [AND change_event.client_type IN (...)]
ORDER BY change_event.change_date_time DESC
LIMIT <limit>
```

Filter builder is implemented in `src/google_ads/queries/change_history.py` as composable functions, parameterized to defeat injection (no string interpolation of user input).

### 4.5 Name resolution

Raw API returns `change_resource_name` as `customers/123/campaigns/456` paths. The tool parses these to extract `(resource_type, resource_id)`. Resolving to human-readable names (`"Pesquisa - Marca"`) requires up to **two additional GAQL calls** that batch all distinct campaign_ids and ad_group_ids from the result set:

```sql
SELECT campaign.id, campaign.name FROM campaign WHERE campaign.id IN (...)
SELECT ad_group.id, ad_group.name FROM ad_group WHERE ad_group.id IN (...)
```

These calls are made only when the result set contains the corresponding resource type (0 if no campaigns appear, 0 if no ad_groups appear). Total quota: **1 to 3 read ops** per tool call. Quota impact still trivial.

If a `resource_id` cannot be resolved (deleted entity, permission edge case), `resource_name` falls back to the path string (`"customers/123/campaigns/456"`) so the row is still surfaced. Skills can detect this gracefully.

### 4.6 Output schema

```json
{
  "customer_id": "1234567890",
  "period": { "from": "2026-05-04", "to": "2026-05-11" },
  "rows": [
    {
      "change_date_time": "2026-05-08T14:23:11+00:00",
      "user_email": "fulano@v4company.com",
      "client_type": "GOOGLE_ADS_UI",
      "resource_type": "CAMPAIGN",
      "resource_id": "987654321",
      "resource_name": "Pesquisa - Marca",
      "operation": "UPDATE",
      "changed_fields": ["status", "campaign_budget"],
      "campaign_id": "987654321",
      "ad_group_id": null
    }
  ],
  "summary": {
    "total_changes": 47,
    "by_user": { "fulano@v4company.com": 32, "auto-apply": 8, "outros": 7 },
    "by_resource_type": { "CAMPAIGN": 12, "AD_GROUP_CRITERION": 30, "BIDDING_STRATEGY": 5 },
    "by_operation": { "UPDATE": 40, "CREATE": 5, "REMOVE": 2 },
    "auto_applied_count": 8
  }
}
```

`summary.by_user` collapses `client_type=GOOGLE_ADS_RECOMMENDATIONS_AUTO_APPLY` rows into the synthetic bucket `"auto-apply"` (regardless of `user_email`, which for auto-apply is typically a Google service account).

`summary.auto_applied_count` is the count of rows with `client_type=GOOGLE_ADS_RECOMMENDATIONS_AUTO_APPLY`. Provided explicitly because skills check this aggressively.

### 4.7 Audit log row

```json
  "params_summary": {
    "date_range": "LAST_7_DAYS",
    "filters_applied": ["resource_types", "client_types"]
  },
  "status": "success"
}
```

## 8. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| `negatives.py` extend for ad_group/shared_set has Google Ads SDK schema peculiarities | Medium | Use `plugin:context7:context7` for current SDK docs before implementing. Tests cover all 3 scopes. |
| `change_event.client_type` enum names drift between SDK versions | Low | Use `.name` for serialization (precedent from 2026-05-06 fixes). Snapshot test for current enum values. |
| Auto-apply detection has false negatives | Low | Snapshot-based test fails CI when enum changes; signals manual review needed. |
| Caller passes wrong scope_id (e.g., ad_group_id when scope=campaign) | Medium | Google Ads API returns clear error; tool surfaces PT-BR friendly error per-item, doesn't fail whole batch. |
| `get_change_history` returns >10k rows, exceeds API page | Low | Schema caps `limit` at 10000. Most workflows use 200-500. |
| Tool name collision risk with existing `add_negative_keywords` | Low | Docstrings clearly distinguish: "atalho do workflow search_terms_report → negatives" vs "negativas conhecidas". |

## 10. Out of scope (explicit)

To prevent scope creep:

- **Not expanding `add_negative_keywords`** to multi-scope (use the new tool for new workflows; existing tool remains campaign-only).
- **Not exposing `change_event.old_resource` / `change_event.new_resource`** (proto-plus diffs). Defer to demand.
- **Not building filter presets** ("structural changes only", "auto-apply changes only"). Agent composes filters.
- **Not adding bulk delete or rollback** of mutations from change_history. Read-only audit only.
- **Not adding filter mode to `add_negatives_from_search_terms`** (compute terms from GAQL internally). Agent calls `get_search_terms_report` first.
- **Phase 3b.2 onwards** is explicitly out of this sprint.
